Read Me First

Why this list exists

Most first-round DevOps/SRE/Cloud/Platform Engineering interviews don't test competitive-programming-level DSA. They're checking if you have solid fundamentals, can explain your thinking out loud, and can handle the practical, scripting-heavy problems (log parsing, file handling, shell one-liners) that actually show up in on-call and tooling work.

So this list leans that way too: patterns over raw volume, and a lot more weight on Python file handling and shell scripting practice than a typical algorithm-only list gives you.

How to use this page

1. Start with the DSA Patterns section and go topic by topic - Arrays & Strings, Two Pointers, Sliding Window, Kadane's/Subarrays, Hashing, Sorting, Recursion, then the Linked List / Stack / Queue / Binary Search basics that show up in infra tooling (caches, queues, bisecting a bad deploy). Short on time? Prioritize Arrays & Strings, Hashing, and Sliding Window first, since those cover most of what actually gets asked.

2. Move to Python File Handling next. These sit closer to real SRE work than most LeetCode problems do, and a handful are original practice prompts (log parsing, CSV/JSON aggregation, safe file writes) because public problem banks barely cover this skill, even though it comes up constantly in real interviews.

3. Finish with Shell Scripting on Files. Bash, grep, awk, sed, plus log analysis and disk management exercises - this is often the part that actually separates candidates in SRE/DevOps loops, more so than the algorithmic round.

4. Check a problem off once you can explain your approach out loud, not just once it passed. That's the real bar interviewers use. (Checkboxes reset when you reload the page, they're just for tracking a single sitting.)

A note on scope

This list runs to roughly 100 problems and exercises across all three practice sections, which is on the thorough side, not a bare minimum. If you're doing a quick refresher instead of a full prep cycle, just treat the top few rows of each pattern/category as the priority set, not the whole page.

Sources

Problems are pulled from LeetCode, NeetCode, GeeksforGeeks, HackerRank, and w3resource. Where no public problem exists for a real interview skill (this happens a lot with file handling and log analysis topics), the row is labeled as a practice exercise with the prompt written out in place of a link. That's called out on purpose, not passed off as a sourced problem.
